[S/W 문제해결 응용] 퀵셀렉트와 K번째 작은 수 (D4)

[문제 스토리]

글로벌 클라우드 플랫폼의 성능 분석관 우진이는 수십만 대의 가상 머신(VM)에서 실시간으로 수집되는 네트워크 패킷 왕복 지연 시간(RTT Latency) 데이터를 모니터링하고 있습니다.
지연 시간 데이터셋에서 특정 순위(분위수, Quantile)에 해당하는 기준값을 신속하게 산출하여 SLA(Service Level Agreement) 위반 여부를 판정해야 합니다.

전체 데이터를 매번 O(N log N)으로 정렬하는 것은 대용량 실시간 처리 환경에서 불필요한 오버헤드를 발생시킵니다.
우진이는 CLRS(Introduction to Algorithms) 9장에서 다루는 **선택 알고리즘(Selection in Expected Linear Time)**인 **퀵셀렉트(Quickselect / RANDOMIZED-SELECT)**를 적용하여 평균 O(N)의 선형 시간에 원하는 K번째 작은 수를 구하고자 합니다.

[알고리즘 개념 학습 - CLRS Ch 9 Medians and Order Statistics]

1. i번째 순서 통계량(i-th Order Statistic):
크기 N인 집합에서 i번째로 작은 원소를 의미합니다. (1번째: 최솟값, N번째: 최댓값, floor((N+1)/2)번째: 중앙값)

2. RANDOMIZED-SELECT 알고리즘:
- 퀵 정렬의 파티션(분할) 메커니즘을 사용하지만, 피벗의 양쪽 구간을 모두 정렬하는 대신 피벗의 위치와 목표 순위 i를 비교하여 i가 속한 한쪽 부분 구간으로만 재귀(또는 반복)를 진행합니다.
- 분할 결과 피벗의 순위가 k일 때:
* i == k : 피벗이 바로 구하고자 하는 원소입니다.
* i < k : 피벗의 왼쪽 부분배열에서 i번째 작은 원소를 계속 탐색합니다.
* i > k : 피벗의 오른쪽 부분배열에서 (i - k)번째 작은 원소를 계속 탐색합니다.
- 분할이 평균적으로 균등하게 이루어지면 T(N) = T(N/2) + O(N) = O(N)의 평균 선형 시간 복잡도를 달성합니다.

3. 피벗 선택 전략 및 최악 케이스 방지:
- 배열이 이미 정렬되어 있거나 역정렬된 경우, 고정된 위치(맨 앞 또는 맨 뒤)를 피벗으로 잡으면 분할이 1 : N-1 로 극단적으로 치우쳐 O(N^2) 최악의 시간 복잡도와 시간 초과가 발생합니다.
- 따라서 난수를 이용해 임의의 위치를 피벗으로 선택하는 **무작위 파티션(Randomized Partition)** 또는 **3-Way 파티션(Dutch National Flag Partition)**을 적용하여 중복 원소 및 정렬된 데이터에서도 분할 균형을 유지해야 합니다.

[검증 요구사항]
N개의 정수 데이터와 Q개의 순위 질의 K1, K2, ..., KQ (1-based)가 주어집니다.
퀵셀렉트 알고리즘을 구현하여 각 Kj번째로 작은 수들을 찾아 공백으로 구분하여 출력하십시오.

[제약 사항 (Java 전용)]

1. 데이터의 개수 N은 1 이상 100,000 이하의 자연수이다.
2. 질의의 수 Q는 1 이상 3 이하의 자연수이다.
3. 순위 K는 1 이상 N 이하의 자연수이다. (1 <= K <= N)
4. 각 원소의 값은 -1,000,000,000 이상 1,000,000,000 이하의 32비트 부호 있는 정수이다.
5. 시간 제한: 10개 테스트케이스 기준 2.0초 이내
6. 메모리 제한: 힙(Heap) 메모리 256MB 이내

[입력]

첫 줄에 총 테스트 케이스의 개수 T가 주어진다.
각 테스트 케이스의 첫 줄에 N과 Q가 공백으로 구분되어 주어진다.
둘째 줄에 Q개의 질의 순위 K1, K2, ..., KQ가 공백으로 구분되어 주어진다.
셋째 줄에 N개의 정수가 공백으로 구분되어 주어진다.

[출력]

각 테스트 케이스마다 '#tc'와 공백을 출력한 후, Q개의 질의에 대한 정답(각 K번째 작은 수)을 순서대로 공백으로 구분하여 한 줄에 출력한다.
형식: `#tc ans1 ans2 ... ansQ`
