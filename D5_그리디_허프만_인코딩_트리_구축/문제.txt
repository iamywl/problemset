[S/W 역량테스트 B형] 허프만 인코딩 트리 구축 (D5)

[문제 설명 - Cormen 알고리즘 16.3 Huffman Codes]
데이터 압축 분야에서 가장 널리 쓰이는 알고리즘 중 하나인 허프만 부호화(Huffman Coding)는 문자의 출현 빈도수에 따라 가변 길이 부호(Variable-length Code)를 부여하여 전체 데이터 크기를 최소화하는 최적 접두어 코드(Optimal Prefix Code) 생성 기법입니다.

[B형 고난도 알고리즘 설계 요구사항]
1. N개의 고유한 문자들과 각 문자의 출현 빈도수 f_1, f_2, ..., f_N이 주어집니다.
2. 우선순위 큐(Min-Heap)를 활용하여 다음과 같이 상향식(Bottom-up)으로 허프만 트리를 구축해야 합니다:
   - 모든 단일 노드를 우선순위 큐에 삽입합니다.
   - 큐에 노드가 2개 이상 있는 동안, 빈도수가 가장 작은 두 노드 x와 y를 꺼냅니다.
   - 두 노드의 빈도수 합(x.freq + y.freq)을 빈도수로 갖는 새로운 부모 노드 z를 생성하고, x와 y를 자식으로 연결한 뒤 z를 다시 큐에 삽입합니다.
   - 이 과정을 N-1번 반복하면 루트 노드 하나가 남게 됩니다.
3. 결과로 생성된 최적 허프만 트리를 이용하여 전체 텍스트를 인코딩할 때 필요한 '총 비트 수'를 구해야 합니다:
   - 총 비트 수 = sum(각 문자 i의 빈도수 f_i * 루트로부터 해당 문자 리프 노드까지의 깊이 d_i)
   - 이는 매 병합 단계에서 합쳐진 두 서브트리의 빈도수 합을 모두 누적한 값과 정확히 일치합니다!
4. N이 최대 100,000에 달하므로, 총 비트 수 계산 결과가 64비트 정수(long)를 초과하지 않도록 철저히 관리해야 합니다.

[제약 사항 (Java 전용)]
1. 문자의 개수 N은 2 이상 100,000 이하의 자연수이다.
2. 각 문자의 출현 빈도수 f_i는 1 이상 1,000,000,000 이하의 자연수이다.
3. 시간 제한: 10개 테스트케이스 기준 2.0초 이내
4. 메모리 제한: 힙(Heap) 메모리 256MB 이내

[입력]
첫 줄에 총 테스트 케이스의 개수 T가 주어진다.
각 테스트 케이스의 첫 줄에 문자의 개수 N이 주어진다.
둘째 줄에 N개 문자의 빈도수가 공백으로 구분되어 주어진다.

[출력]
각 테스트 케이스마다 '#tc'와 공백을 출력한 후, 최적 인코딩에 필요한 총 비트 수(총 가중 경로 길이)를 출력한다.
