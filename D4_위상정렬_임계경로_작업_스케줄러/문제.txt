[S/W 문제해결 심화] 임계경로 작업 스케줄러 (D4)

[복합 제약 조건 설명 - Critical Path Method (CPM)]
대형 건설 프로젝트에는 1번부터 N번까지 총 N개의 작업이 있습니다.
각 작업 i는 완료하는 데 t_i 시간이 소요되며, 작업들 간의 선후 관계가 방향 비순환 그래프(DAG)로 주어집니다.
선행 작업들이 모두 완료되어야만 다음 작업을 시작할 수 있습니다.
프로젝트 매니저는 (1) 전체 프로젝트를 완료하기 위한 '최소 소요 시간'과, (2) 1분이라도 지연되면 전체 프로젝트의 완료 시간이 지연되는 '임계 작업(Critical Activity)'의 총 개수를 파악해야 합니다.

[복합 해결 조건]
1. 정방향 위상 정렬:
   - 각 작업의 가장 빠른 시작 가능 시각 `early[i]`를 계산합니다:
     early[v] = max_{(u, v)} (early[u] + t_u)
   - 전체 프로젝트 최소 완료 시간 T_total = max_i (early[i] + t_i).
2. 역방향 위상 정렬:
   - 각 작업의 가장 늦게 시작해도 전체 완료 시간에 영향을 주지 않는 시각 `late[i]`를 역추적합니다:
     late[u] = min_{(u, v)} (late[v] - t_u)
3. 임계 작업 판별:
   - early[i] == late[i] 인 작업은 지연 여유 시간(Slack)이 0이므로, 전체 일정을 좌우하는 '임계 작업'입니다.
4. 최소 총 완료 시간과 임계 작업의 총 개수를 모두 구해야 합니다.

[제약 사항 (Java 전용)]
1. 작업의 수 N은 1 이상 10,000 이하의 자연수이다.
2. 선후 관계의 수 M은 0 이상 100,000 이하의 정수이다.
3. 각 작업의 소요 시간 t_i는 1 이상 1,000 이하의 자연수이다.
4. 시간 제한: 10개 테스트케이스 기준 2.0초 이내
5. 메모리 제한: 힙(Heap) 메모리 256MB 이내

[입력]
첫 줄에 총 테스트 케이스의 개수 T가 주어진다.
각 테스트 케이스의 첫 줄에 N과 M이 공백으로 구분되어 주어진다.
둘째 줄에 1번부터 N번까지 각 작업의 소요 시간 t_1, ..., t_N이 공백으로 구분되어 주어진다.
이어지는 M개의 줄에는 선행 작업 u와 후행 작업 v가 공백으로 구분되어 주어진다.

[출력]
각 테스트 케이스마다 '#tc'와 공백을 출력한 후, 전체 프로젝트의 최소 완료 시간과 임계 작업의 개수를 공백으로 구분하여 출력한다.
