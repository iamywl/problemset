[S/W 문제해결 기초] 단순 활동 선택 (D2)

[알고리즘 개념 및 원리 학습 - 활동 선택 문제(Activity Selection Problem, CLRS 16.1)]
하나의 회의실이 있고, 여러 개의 회의가 시작 시간과 종료 시간을 가질 때, 서로 시간이 겹치지 않게 하면서 진행할 수 있는 '최대 회의 개수'를 선택하는 고전적인 문제입니다.

[탐욕적 선택 원리]
어떤 기준으로 회의를 선택해야 가장 많은 회의를 진행할 수 있을까요?
1. 시작 시간이 가장 이른 회의? -> 시작이 빨라도 회의가 너무 늦게 끝나면 다른 회의를 못하게 되므로 틀립니다.
2. 회의 시간이 가장 짧은 회의? -> 짧은 회의가 다른 회의들의 중간에 걸쳐 있으면 최적이 아닐 수 있습니다.
3. '종료 시간(End Time)이 가장 빠른 회의'! -> 정답!
종료 시간이 가장 빠를수록 회의실이 일찍 비게 되므로, 이후에 더 많은 회의를 선택할 수 있는 여유 시간이 최대한 많이 남게 됩니다.

[동작 단계]
1. 모든 회의를 '종료 시간' 기준으로 오름차순 정렬합니다. (종료 시간이 같다면 시작 시간 기준 정렬)
2. 첫 번째 회의를 선택합니다.
3. 이후 회의들을 순회하면서, 현재 회의의 시작 시간이 '이전에 선택한 회의의 종료 시간' 이상인 경우에만 선택하고 종료 시간을 갱신합니다.

[문제 설명]
N개의 회의에 대해 각 회의의 시작 시간 s_i와 끝나는 시간 e_i가 주어질 때, 한 회의실에서 진행할 수 있는 회의의 최대 개수를 구하는 프로그램을 작성하십시오. 회의는 끝남과 동시에 다음 회의가 시작될 수 있습니다.

[제약 사항 (Java 전용)]
1. 회의의 수 N은 1 이상 100,000 이하의 자연수이다.
2. 시작 시간과 종료 시간은 0 이상 2,000,000,000 이하의 정수이며, 항상 시작 시간 <= 종료 시간이다.
3. 시간 제한: 10개 테스트케이스 기준 2.0초 이내
4. 메모리 제한: 힙(Heap) 메모리 256MB 이내

[입력]
첫 줄에 총 테스트 케이스의 개수 T가 주어진다.
각 테스트 케이스의 첫 줄에 회의의 수 N이 주어진다.
이어지는 N개의 줄에는 각 회의의 시작 시간 s_i와 종료 시간 e_i가 공백으로 구분되어 주어진다.

[출력]
각 테스트 케이스마다 '#tc'와 공백을 출력한 후, 진행할 수 있는 최대 회의 개수를 출력한다.
