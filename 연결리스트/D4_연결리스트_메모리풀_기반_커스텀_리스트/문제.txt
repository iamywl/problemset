[S/W 문제해결 심화] 메모리풀 기반 커스텀 리스트 (D4)

[문제 설명 및 Zero-GC 원리]
삼성 B형(Pro) 실전 코딩 테스트에서는 수십만 건의 노드 동적 생성 시 자바의 `new` 연산자로 인한 가비지 컬렉터(GC) 오버헤드를 원천 차단하기 위해, 정적 배열 메모리 풀(Static Node Pool)을 미리 할당하고 정수 인덱스 포인터로 연결 관계를 관리하는 커스텀 이중 연결 리스트(DLL)를 구축해야 합니다.

정적 노드 풀을 기반으로 다음 4가지 핵심 연산을 고속으로 처리하는 시스템을 구현하십시오:
1. `ADD_FRONT X`: 정수 X를 리스트의 맨 앞에 삽입
2. `ADD_BACK X`: 정수 X를 리스트의 맨 뒤에 삽입
3. `DEL_VAL X`: 리스트에서 값이 X인 노드를 찾아 첫 번째로 발견된 노드를 삭제 (노드가 없으면 무시)
4. `QUERY_K K`: 리스트의 앞에서부터 K번째(1-indexed) 노드의 값을 출력 (K가 리스트 크기보다 크면 -1)

모든 쿼리의 결과를 종합하여 공백으로 구분해 출력하십시오.

[제약 사항 (Java 전용)]
1. 주어지는 총 쿼리 수 M은 1 이상 10,000 이하의 자연수이다.
2. 입력되는 정수 X는 1 이상 100,000 이하의 자연수이다.
3. Zero-GC 정적 배열 풀을 활용하여 시간 복잡도와 메모리를 최적화한다.
4. 시간 제한: 10개 테스트케이스 기준 2.0초 이내
5. 메모리 제한: 힙(Heap) 메모리 256MB 이내

[입력]
첫 줄에 총 테스트케이스의 개수 T가 주어진다.
각 테스트케이스의 첫 줄에 쿼리의 수 M이 주어진다.
이어지는 M개의 줄에 걸쳐 쿼리가 한 줄에 하나씩 주어진다.

[출력]
각 테스트케이스마다 '#tc'와 공백을 출력한 후, QUERY_K 연산의 결과들을 공백으로 구분하여 출력한다. (쿼리가 없다면 빈 줄)
